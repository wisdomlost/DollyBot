# 运镜车示教与回放

## 首次标定

在 Keil 打开 `firmware/stm32/MDK-ARM/DollyBot.uvprojx`。底盘只需填写一个距离参数，位于 `firmware/stm32/board/chassis_config.h`。

1. 车头朝前，在平地沿直线推车，量出起点到终点的距离（毫米）。在 Keil 的 Watch 中分别记下推车前后的 `wheel_counts[0..3]`，轮序为左前、右前、左后、右后。
2. **惯导系数 = 直推距离（毫米）÷ 四轮向前计数增量之和。** 四轮向前滚动时，方向修正后的计数应为正且幅度接近。如果有轮子反号，检查该轮 A/B 接线或方向配置。固件把麦轮运动学的四轮平均因子 `1/4` 合并进这个系数。前进位移用 `(左前 + 右前 + 左后 + 右后) × 惯导系数`，向右位移用 `(左前 − 右前 − 左后 + 右后) × 惯导系数`。
3. 将结果填入 `#define 惯导系数` 并重新构建。出厂配置为 `0.0f`，允许读取传感器，电机保持关闭。航向和转速反馈取自陀螺仪。
4. 架空轮组低速核对前进、向右平移、顺时针转向。落地后复测相同距离，再用横移和往返路线记录滑移对回放的影响。

## 拍摄操作

1. 手机完成经典蓝牙配对，打开 App 连接 DollyBot。将车放在有标记的原点并对齐车头，停稳后点击校准。四轮静止和 IMU 平稳持续至少 600 ms 才能建立坐标参考。
2. 在控制页选择连续录制、推车或关键点取点。推车模式释放电机，按 50 ms 采样。连续录制同时记录车身位姿与两轴舵机指令角。结束时给路线命名。
3. 在“我的轨迹”中打开路线。可调整倍率、循环次数，关键点还可选择直线或平滑曲线，并编辑每点的停留及云台指令角。保存后点击“下发”。手机将预览时间轴转换成带时间戳的执行点，STM32 校验后保存最近一次完整任务。单条上限为 4096 个执行点，20 Hz 连续录制三分钟含首点需要 3601 个点。
4. 点击“开始车端回放”。若车辆搬动过或重新上电，先按原标记的位置和朝向重新校准。确认后车辆低速移至首点、转至录制朝向，再开始拍摄。循环间返回首点，最后一轮停在末点。
5. 停止按钮撤销本次运动。回放期间 App 每 50 ms 发送绑定会话和运行编号的授权，期限为 500 ms。新会话、失联、传感器异常及持续跟踪失败都会停机。云台无角度回读，实拍时应检查实际取景和机械行程。

## 电池和过流保护

| 采样 | STM32 通道 | 换算与初始设置 |
|---|---|---|
| 电池电压 `ADC_BAT` | PC0 / ADC1_IN10 | 100 kΩ / 22 kΩ 分压，电池电压为 ADC 电压的 122/22 倍。工作范围为 9.6–13.2 V。 |
| 电机总电流 `ADC_SPARE5` | PA5 / ADC1_IN5 | 0.5 mΩ 分流，INA181A1 放大 20 倍，10 mV/A。达到 8.0 A 并持续 100 ms 停机。 |
| 云台总电流 `GIMBAL_ADC` | PC1 / ADC1_IN11 | 10 mΩ 分流，INA181A1 放大 20 倍，200 mV/A。达到 2.5 A 并持续 500 ms 停机。 |

ADC 换算暂按 3.3 V 参考电压。App 控制页和设备页显示电池电压和估算电量，设备页另显示两个支路的总电流。估算电量按滤波后的 3S 电池电压在 9.6 V（0%）至 12.6 V（100%）间线性换算，随电池压降和负载变化。

任一路过流或 ADC 转换超时，STM32 本地停止电机 PWM、拉低 `DRV_EN` 并关闭云台 PWM 和 `GIMBAL_PWR_EN`。电机母线由板上的手动开关控制。故障锁存期间，手动控制和回放保持停机，故障排除后重新上电。阈值和持续时间在 `firmware/stm32/board/power_config.h` 中设置，初始值待实车确认。

STM32 每 200 ms 发送一帧 `0x92 POWER_STATUS`，新增锁存故障时立即发送。ESP32 通过蓝牙转发，原 34 字节 `0x90 STATUS` 格式继续适用。10 字节电源帧按小端排列。

| 字节偏移 | 内容 |
|---|---|
| 0 | 电池电压，u16，mV |
| 2 | 电机总电流，u32，mA |
| 6 | 云台总电流，u16，mA |
| 8 | 估算电量，u8，0–100 |
| 9 | Bit 0 电机过流，bit 1 云台过流，bit 2 ADC 故障，bit 3 电池电压超出范围 |

采样失败时，前四个字段的所有位均置一。App 在未收到电源帧或读数过期时显示暂无数据。

## 构建与验收

| 对象 | 入口与检查 |
|---|---|
| STM32 | Keil MDK 工程使用 Arm Compiler 6，链接脚本将最后两个 128 KiB 扇区留给轨迹。CubeMX 配置用于查看引脚与外设，实际固件使用 `board/` 内的寄存器驱动。 |
| ESP32 | 在 `firmware/esp32/` 内使用 ESP-IDF v5.5.4 的 `idf.py build`。根目录工程用于原有网页控制。 |
| Android | 在 `android/` 内使用 Gradle Wrapper 构建 `testDebugUnitTest assembleDebug`。需要 Android SDK 37.0 与 Gradle 配置指定的 JDK。Windows 上使用纯英文构建路径可避免 Gradle 测试工作进程加载类失败。 |
| 主机与模拟器 | 在仓库根目录执行 `tools/test.ps1`，使用 ESP-IDF 的 cJSON。进入 `android/outside_androidstudio/`，在装有 pyserial 的 Python 环境执行 `python -m unittest discover -s simulator/tests`。|
| 实车 | 先空载架空验证停机方向和电机控制，然后在地面标注首点、终点和朝向，重复直线、横移、组合转弯与原地转向。分别记录外部测量的终点距离误差、车头角度误差、各轮实拍时长和云台构图。通过断开蓝牙和停止发送授权检查停机。|

云台角度、控制增益及到点容差为初始调试值，需由实车确认。片内 Flash 在车辆停稳时写入，先写备用槽，读回校验后才写有效标记。串口 RX 使用 DMA 在写入期间继续收包。

Kira 参考工程中的里程增量积分和反馈跟踪思路用于本车实现。其 RT1064 的 Flash 地址、标定系数和电机参数均未作为本车实测值使用。
