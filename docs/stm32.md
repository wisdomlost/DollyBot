# STM32 接入边界

`motion_link_init/set/is_simulated` 是运动接口边界，网络层不触碰 UART。当前实现只写 ESP32 日志，不初始化任何 GPIO，不假定开发板引脚；不会发送串口电机指令。未来新增 UART 后端和独立 RX/TX 任务，保持现有模拟后端供回归使用。

建议 UART1、115200 8N1、3.3 V TTL、共地、TX/RX 交叉；具体引脚需结合 ESP32 模组原理图配置，避开 Flash/启动绑带/日志 UART0。不要直接接 5 V。

建议二进制帧：同步字、版本、消息类型、会话 ID、seq、长度、有界负载、CRC16-CCITT。首先明确端序、CRC 初值/覆盖范围、单位、最大帧长及转义或重同步策略，再分别实现双方解析器与测试向量。RX 环形缓冲、帧间超时、长度上限、CRC、重放检查必须独立于网页协议。

TX 用有界邮箱保存最新目标，避免旧 drive 排队；停止具有优先级。禁止在 control 锁内等待 UART、ACK 或硬件，`motion_link_set` 必须有界、非阻塞。STM32 自行执行速度限幅、加速度限制和独立心跳超时停车，ESP32 不应成为唯一运动保护。

握手报告固件版本、能力与状态；STM32 返回 ACK、实测速度、编码器里程、故障。链路断开应拒绝 drive，并清除目标；重连必须重新授权动作。新增状态快照区分 requested/measured、来源和采样时间，只有真实返回后才能置 stm32_connected=true 和 simulated=false。

轨迹录制/里程计/回放执行留在 STM32，ESP32 负责命令、元数据和可视化；回放必须有显式状态机、停止优先级及控制权冲突处理。
