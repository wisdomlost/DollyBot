# DollyBot 蓝牙模拟车

## 启动

在 PowerShell 中进入工程根目录，再启动模拟器。

```powershell
Set-Location 'D:\Android\project\Dollybot'
& 'D:\anaconda\python.exe' -m simulator.app --port COM4
```

上报周期默认 50 ms，可在打开串口前通过窗口中的“上报周期 (ms)”调整，也可从命令行指定：

```powershell
& 'D:\anaconda\python.exe' -m simulator.app --port COM4 --status-interval-ms 100
```

周期范围为 20–1000 ms，打开串口后锁定设置；关闭串口后可以修改。该设置统一控制周期 STATUS 上报，开始和结束时的即时样本不受周期限制。调度延迟时跳过错过的周期，不补发积压样本。

当前 Anaconda 已具备 pyserial 与 tkinter。使用其他 Python 环境时安装 pyserial。

```powershell
python -m pip install pyserial
```

模拟器窗口可以刷新、选择和打开串口，显示小车位置、朝向、云台角度、连续轨迹、关键点及协议错误数量。

## 手机连接

1. 在 Windows 蓝牙设置的“更多蓝牙设置 / COM 端口”中添加“传入”端口，保存后确认实际 COM 编号。
2. 在 Android 系统蓝牙设置中与电脑配对。
3. 模拟器打开该入站端口，手机安装工程生成的 APK。
4. App 设备页点击“刷新已配对设备”，允许“附近设备”权限，选中电脑后连接。
5. 等待握手成功，停稳后校准。校准建立新的坐标参考系。
6. 在控制页点击“录制”，选择“连续录制”或“取点”，再点击“开始”。连续录制自动记录；取点模式点击“取点”记录当前位姿。
7. 控制页点击“停止”，等待最终数据后输入名称保存。两个示教查看页只显示数据，切换页面时录制继续。
8. 轨迹页的“我的轨迹”按连续轨迹、点轨迹分类。打开轨迹可重命名、删除及离线播放预览，点轨迹还可调整点序和删除点；修改后点击“保存修改”。

### 推车录制联调

1. 手机连接并校准设备，处理完已有待保存草稿后，在“录制”菜单中选择“推车”。App 自动清零车身控制，等待 STOP 确认后发送 TEACH_BEGIN(mode=3)，显示“等待车端确认”。成功收到开始 ACK 后才显示为录制中。
2. 模拟车自动生成半径 500 mm、车身转向速度 20°/s 的圆弧，起点和朝向沿用开始时的位姿。窗口中紫色轨迹和“推车采样”数量同步增长。该运动模拟人手推动，与 MOTION 指令无关。
3. App 暂停车身平移和旋转控制，云台仍可操作。默认模拟云台在初始角度附近按 10 秒周期变化，偏航幅度 30°、俯仰幅度 15°，角度不超过 ±180°；收到首条 App 云台指令后，本次录制改为保持 App 指定角度。
4. 录制期间可打开“查看连续示教”核对实时轨迹、时长和采样数；切换页面不会结束录制。App 按回传位姿原样记录，不以控件目标角度代替实测角度。
5. 返回控制页点击“停止”。最终采样在结束 ACK 之前发送，App 校验点数并写入本地草稿，再选择命名保存、稍后保存或放弃。保存结果位于“我的轨迹 → 连续轨迹”，可离线播放。
6. 分别使用 50 ms、100 ms 周期重复测试，核对模拟车与手机的采样总数、首末车身位置及云台角度。断连或退后台时已有有效采样保存为不完整草稿；开始 ACK 前的数据仅暂存，未确认开始就断连不会生成轨迹。

录制中收到重复索引时忽略，索引缺失时标记不完整；其他会话或录制编号的数据不会混入当前推车轨迹。坐标系变化时中断并保留已有有效采样。录制中不持续写盘，进程意外终止会丢失尚未停止保存的数据。

若打开 COM4 提示找不到文件，先确认该端口已在 Windows 保存且属于“传入”。模拟器中的端口下拉框会列出系统当前可用端口。端口被其他串口程序占用时，需要先关闭占用程序。

手机轨迹和停止后的未命名草稿保存在本地 SQLite 中，重启后可继续查看或命名保存。模拟器中的记录保留在当前进程内。编辑页的动画仅在手机内播放，不驱动模拟车。

## 协议 V1

全部多字节整数为小端序。SPP UUID 为 `00001101-0000-1000-8000-00805F9B34FB`。

```text
A5 5A | VER:u8 | TYPE:u8 | SEQ:u16 | LEN:u16 | SESSION:u32 | PAYLOAD | CRC:u16
```

帧总长为 14 + LEN。VER 为 1，LEN 最大 256。CRC-16/CCITT-FALSE 覆盖 VER 至数据区末尾，初值 FFFF、多项式 1021、不反射、不异或，CRC 以小端序写入。标准测试串 123456789 的 CRC 为 29B1。

手机为每次连接生成非零随机 SESSION，先发 HELLO。电脑仅接收当前会话的后续指令。请求 SEQ 为循环递增 u16，ACK 与 POINT 回显请求序号，STATUS 使用独立递增序号。

| TYPE | 方向 | PAYLOAD |
| --- | --- | --- |
| 01 HELLO | 手机到电脑 | 空 |
| 02 PING | 手机到电脑 | 空 |
| 10 MOTION | 手机到电脑 | strafe:i16, forward:i16, rotation:i16 |
| 11 GIMBAL | 手机到电脑 | yaw:i16, pitch:i16 |
| 12 STOP | 手机到电脑 | 空 |
| 20 CALIBRATE | 手机到电脑 | 空 |
| 30 TEACH_BEGIN | 手机到电脑 | mode:u8, frame_id:u32 |
| 31 TEACH_END | 手机到电脑 | teach_id:u32 |
| 32 TAKE_POINT | 手机到电脑 | teach_id:u32 |
| 40 TRAJECTORY_BEGIN | 手机到电脑 | kind:u8, flags:u8, name_bytes:u32, point_count:u32 |
| 41 TRAJECTORY_DATA | 手机到电脑 | offset:u32, data:1–252 字节 |
| 42 TRAJECTORY_COMMIT | 手机到电脑 | 空 |
| 80 ACK | 电脑到手机 | request_type:u8, result:u8, value:u32 |
| 90 STATUS | 电脑到手机 | 下文定义的 34 字节位姿状态 |
| 91 POINT | 电脑到手机 | 下文定义的 30 字节取点快照 |

MOTION 分量为 -1000 到 1000，侧移向右、前进向前、右转为正。默认轴向速度为 200 mm/s，旋转速度为 90°/s。所有角度字段单位为 0.01°，云台范围为 ±180°，右偏航和上俯仰为正。

世界坐标单位为毫米，+X 向右、+Y 向上，车身 yaw=0 指向 +Y，顺时针为正。mode=0 为空闲、1 为连续示教、2 为关键点示教、3 为推车示教。推车模式使用相同的 TEACH_BEGIN、STATUS 和 TEACH_END 数据结构，协议版本仍为 1。未实现 mode=3 的车端应返回不支持或参数错误，App 提示失败并允许重试。

```text
STATUS
t_ms:u32, frame_id:u32, x_mm:i32, y_mm:i32,
yaw:i16, gimbal_yaw:i16, gimbal_pitch:i16,
mode:u8, flags:u8, teach_id:u32, point_index:u32, last_motion_seq:u16

POINT
teach_id:u32, point_index:u32, t_ms:u32, frame_id:u32,
x_mm:i32, y_mm:i32, yaw:i16, gimbal_yaw:i16, gimbal_pitch:i16
```

t_ms 是电脑当前连接会话内的单调时间。flags 的 bit0 表示已校准，bit1 表示运动超时停车。连续和推车模式的 point_index 从 1 开始，每个 STATUS 对应一个采样。关键点模式下表示累计取点数，点位数据通过 POINT 返回。

ACK result 为 0 成功、1 状态不允许、2 未校准、3 参数错误、4 坐标系不匹配、5 不支持的命令或版本。value 在校准成功时为 frame_id，开始示教时为 teach_id，结束示教或提交轨迹时为最终点数，其他情况为零。取点成功直接返回 POINT，失败返回 ACK。

在 App 的“轨迹 → 我的轨迹”中点击“下发”。轨迹类型 kind 为 1（连续，含推车）或 2（关键点），flags bit0 表示原录制不完整。数据流由 UTF-8 名称和按保存顺序排列的位姿组成。每个位姿为 22 字节，字段与 STATUS 的前 7 个字段相同，保留原采样时间和坐标系。offset 从 0 开始，以数据流字节为单位。名称和点数必须非零，数据总长度最多为 u32 的最大值。接收端确认每帧，收齐并提交后才更新最近收到的轨迹。新下发或会话结束会丢弃未提交数据。模拟车窗口显示最近收到的轨迹及点数，下发只接收数据。

MOTION 与 GIMBAL 成功时不发送 ACK，参数错误时返回 ACK。其他命令等待响应 1 秒，最多重试两次，使用原序号。电脑缓存最近 256 条离散请求的完整响应。

手机以 20 Hz 刷新运动指令，松手立即发送零输入。推车开始请求至结束收尾期间暂停发送 MOTION，GIMBAL 和每秒心跳继续工作；推车期间 MOTION 返回状态不允许，STOP 仅清除电机输入，不结束人工推动。300 ms 无运动指令则停车，云台保持最后角度。3 秒没有有效手机消息则中断示教。连续和推车示教开始时先 ACK、再补首个即时样本；结束时先补最终样本、再 ACK 最终点数。

## 验证

```powershell
& 'D:\anaconda\python.exe' -m unittest discover -s simulator/tests -v
```

Android 单元测试包含协议样例、拆包粘包、CRC 错误恢复、字段顺序和预览插值检查。仪器测试覆盖 SQLite 持久化、草稿恢复、编辑保存、录制按钮状态、只读示教画布，以及控制和导航行为。
